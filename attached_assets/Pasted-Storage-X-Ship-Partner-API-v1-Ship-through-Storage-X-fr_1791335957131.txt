Overview
Every request is authenticated with an API key we issue you, sent as a bearer token — there is no session or cookie involved. Every response is JSON, including errors, except the raw-PDF label endpoint.

Authentication
Every request
Authorization: Bearer [REDACTED_STORAGE_X_API_KEY]
Content-Type: application/json
Copy
Anyone holding the key can create, edit and cancel shipments on your account — and on the account of any merchant we have enabled you to ship for. Keep it server-side only, and ask us to rotate it if it's ever exposed.

Shipping for your merchants
Skip this section unless we have issued you handoff codes. By default every parcel you create is billed to you, and nothing here changes that.

If you resell for merchants who hold their own account with us, we issue you one handoff code per merchant. Send it as merchantRef and the parcel is billed to that merchant — their rate card prices it, their wallet is charged, their COD is settled to them. You stay the one who creates, tracks, edits and cancels it, exactly as with your own parcels.

A code looks like this
SXH-K7P2M9QRTV
Copy
It is not a credential — it does nothing without your own API key — so you can store it against the merchant in your database, log it, and ask us for it again. A code belongs to one partner and one merchant; presented with anyone else's key it is refused.

merchantRef	optional	On Create and Quote, at the top level of the body. Omitted means the parcel is billed to you. handoffCode and onBehalfOf are accepted as names for the same field.

Send it on Quote too. Price comes from the merchant's rate card, so quoting without it prices the parcel at your rates and the figure will not match what Create charges.

Everything after Create needs nothing extra — Track, Label, Update and Cancel all work on the tracking number as usual, because the parcel remembers that you created it.

externalOrderId is deduplicated per merchant, so two of your merchants can each use ORD-1 without colliding.

A malformed code is a 400 invalid_merchant_ref — your payload to fix. A well-formed code you are not enabled for is a 403 merchant_not_permitted, which also covers a merchant whose account is suspended and a code we have withdrawn. Withdrawing one stops new parcels only; parcels you already created stay yours to track and cancel.

The national address short code
Saudi Arabia's National Address short code — four Latin letters and four digits, e.g. RRRD6636 — is required on both the pickup and recipient side of every shipment you create.

Accepted as
Case-insensitive — rrrd6636 and RRRD6636 both work, we upper-case it. Whitespace is stripped.

Rejected
Missing or malformed returns 400 invalid_national_address (recipient) or 400 invalid_pickup_national_address (pickup) on create. On update it's only checked if you send it.

Money fields
Every amount you send us can be given in riyals or halalas — riyals is the default; sending halalas is optional, for whichever is easier on your side.

What you send
Use the plain field — cod.amount, codAmount — with a riyal value, e.g. 150 for 150.00 SAR. Prefer an integer on your end instead? Send cod.amountMinor / codAmountMinor — halalas, SAR's minor unit (1 SAR = 100 halalas) — and we use that instead. Sending both is fine; the halala value wins.

What we send back
Always halalas, and always as a string — "totalMinor": "3120" means 31.20 SAR. Divide by 100 for riyals. It's a string because these are large integers under the hood; floating-point riyals and rounding money don't mix safely, so every *Minor field you get back stays an exact integer instead of a float.

Coverage
Check which cities you can ship to or from before committing to an order. Pickup and delivery are answered separately — they're genuinely different questions on our side, so treat pickupAvailable as a strong signal, not an absolute guarantee. We don't say which carrier a lane runs through — that's between us and them.

GET
/coverage
Every serviceable city, optionally filtered and paginated. Called with no query parameters, pagination is opt-in — it returns everything at once with pagination: null.

Get a price quote
What would this cost? Same nested shape as Create, minus the fields pricing has no use for — and the exact same pricing engine Create itself uses, so a quote here is never a separate estimate that could drift from what you're actually charged.

POST
/quote
serviceable: false is a normal answer (no rate configured for that combination) — not an error, and not a reason to retry.

Create a shipment
Creates a shipment and immediately raises a pickup request — there's no separate step. Safe to retry: a second call with the same externalOrderId returns the existing shipment instead of a duplicate. externalOrderId only has to be unique to you — a different partner can use the exact same order id independently.

Track a shipment
Every event's code, label and labelAr are the exact same values List tracking statuses gives for that code — never a different phrase for the same status. Match an event's code straight back to that list rather than parsing label text.

GET
/shipments/{trackingNumber}
Response — 200
{
  "trackingNumber": "SXS10394822",
  "status": "awaiting_pickup",
  "custody": "with_merchant",
  "events": [
    {
      "occurredAt": "2026-09-24T09:12:00Z",
      "code": "awaiting_pickup",
      "label": "Awaiting pickup",
      "labelAr": "بانتظار الاستلام",
      "location": "Riyadh"
    }
  ]
}
Copy
Two further keys, carrier and carrierAwb, appear only when a shipment went out with a partner carrier and your account is configured to see them. They are absent otherwise — never present and null — so do not treat a missing key as a field you failed to read. trackingNumber stays the reference for every other call whatever those keys say.

List tracking statuses
Every value you can ever see in status or custody, with a description — the full reference for whatever state machine you build around Track. status answers what's happening; custody answers who is physically holding the parcel right now. They always move together, but they're genuinely different questions.

GET
/statuses
Static reference data — no tracking number, nothing tenant-specific. Safe to cache on your side; call it once and keep the list.

Response — 200 (truncated — the real response lists all 19 statuses and 10 custody states)

Update a shipment
Edits a shipment while it's still yours to change — before it reaches a hub. Send only the fields you're changing. If weight, city or COD change on a shipment already charged for, it's repriced and the difference posted — never a silent second charge.

/shipments/{trackingNumber}

recipientName / recipientPhone	optional	
addressLine / nationalAddress	optional	nationalAddress validated if present.
city / district	optional	Triggers repricing and re-routing.

codAmount / codMethod	optional	codAmount in riyals, e.g. 200. Triggers repricing. codAmountMinor (halalas) also accepted — see Money fields above.

Print a label
The label that belongs on the box. Normally the same bilingual, barcoded label our own operations team prints, with sort and route codes frozen on first print so printing twice always shows the same codes. Where a shipment is carried by a partner that collects it from you, this returns THAT carrier's label instead — print what you are given, because the driver who arrives can only scan their own barcode.

GET
/shipments/{trackingNumber}/label
Raw PDF bytes (Content-Type: application/pdf). Refused with 409 shipment_closed once a shipment is cancelled, lost, damaged or returned, and with 409 label_pending while a partner carrier's label is still being issued — retry shortly.

GET
/shipments/{trackingNumber}/label?format=url
A permanent link instead of bytes — safe to store once against your own order, since it never changes even if the label is regenerated later.

Response — 200
{
  "trackingNumber": "SXS10394822",
  "url": "https://.../partner-labels/b6e2....pdf?token=..."
}
Copy
